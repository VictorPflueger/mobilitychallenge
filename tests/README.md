# Tests (optional, for developers)

Dispatch Lab itself needs no Node.js, npm, Python or build step. These scripts are the checks behind it: that the browser engine is the challenge's Python environment, that the page shows what the engine computed, and that it follows Vici. Run them after changing code or data. GitHub Actions runs the Node.js and browser suites on every push to this branch (`.github/workflows/tests.yml`).

Every suite covers both maps, Neu-Frankfurt (`frankfurt`) and Köln (`koeln`). Their files are in `data/<map>/` (the map, the plans, the Python runner's scores) and `fixtures/<map>/` (the Python traces and the rules); `lib/maps.mjs` lists them, the same list as the page's `js/maps.js` and the Python tools' `tools/maps.py`. The Node.js suites that take arguments run one map when named (`node tests/engine.mjs --map koeln`, `node tests/story.mjs koeln`).

## The Python side

The fixtures come from the challenge's own Python environment. With a checkout of the challenge (its `uv` environment set up as its README says, flatland-rl 4.2.2):

```
<challenge>/.venv/bin/python -B tools/export_fixtures.py --repo <challenge> --check   rebuild and compare, both maps
<challenge>/.venv/bin/python -B tools/export_fixtures.py --repo <challenge>           rewrite tests/fixtures/<map>/ and data/<map>/reference.json
<challenge>/.venv/bin/python -B tools/check_estimate.py --repo <challenge>            the estimate's plan, step by step
<challenge>/.venv/bin/python -B tools/check_estimate.py --repo <challenge> --write    rewrite data/frankfurt/estimate_actions.json
<challenge>/.venv/bin/python -B tools/check_plan.py --repo <challenge>                each map's plan is PlannerController's
```

Every script but `check_estimate.py` (Neu-Frankfurt only) takes `--map frankfurt` or `--map koeln` to run one map. `export_fixtures.py` also writes the floor (`tools/score_floor.py`, on flatland's own rail) into `tests/fixtures/<map>/rules.json`, after checking the timing it assumes in every recorded run. `check_estimate.py` runs `tools/estimate_planner.py` through the challenge's runner and checks after every step that each train is where its booked route says, that every train arrives at its planned step, and that the actions are those in `data/frankfurt/estimate_actions.json`. `check_plan.py` replans each map (about two minutes for Neu-Frankfurt, five for Köln) and compares the actions with `data/<map>/planner_actions.json` (`--write` rewrites it); it needs the planner's two files (`planner_core.py`, `plannercontroller.py`) in `<challenge>/src/controller/`, which are not part of this repository. These scripts only wrap the runner to record what happens; they change nothing in the environment.

## Setup for the browser suites

You need Node.js 20 or later and Playwright with Chromium. Install them once, outside this folder:

```
npm install -g playwright@1.56.0
npx playwright install chromium
```

Then run with Node's module path pointing at the global packages:

```
NODE_PATH="$(npm root -g)" node tests/run-all.mjs
```

On Windows PowerShell: `$env:NODE_PATH = (npm root -g); node tests/run-all.mjs`.

Options (environment variables):
- `PLAYWRIGHT_MODULE`: path to a Playwright installation, instead of `NODE_PATH`.
- `CHROME_PATH`: use this Chrome or Chromium binary instead of Playwright's.
- `DL_TEST_OUT`: folder for screenshots (default: the system temp folder, `dispatch-lab-tests/`).

The suites serve the page on `127.0.0.1`: smoke on port 8765, layout on 8766, hexagon on a random one between 8790 and 9089. Every request to another host is blocked.
